# S2-T07 — Implementación real de autenticación con Supabase Auth

## Datos de la tarea

- **Sprint:** 2
- **Prioridad:** 750
- **Responsable nominal:** RRC
- **Estado inicial:** pendiente
- **Dependencias:** S2-T06
- **Rama:** `feat/S2-T07-autenticacion-supabase`
- **Base temporal:** rama de S2-T06; integrar S2-T06 antes que esta rama

## Objetivo

Implementar `RepositorioAuth` con `supabase-kt`, activar únicamente esa
implementación real mediante Hilt y recibir el enlace de recuperación acordado
en S2-T06 para abrir P-18. Las demás interfaces de repositorio continúan
enlazadas a sus implementaciones falsas.

## Referencias

- `docs/tecnico/CONTRATOS-API.md`, sección «Autenticación · RepositorioAuth» y
  tabla de errores.
- `docs/tecnico/ARQUITECTURA.md`, reglas de dependencias y repositorios.

  recuperación y enlaces profundos móviles.

## Alcance

1. Configurar el plugin Auth del cliente existente con esquema
   `mx.donchambitas.app` y host `auth`, usando solo `BuildConfig.SUPABASE_URL`
   y `BuildConfig.SUPABASE_ANON_KEY`.
2. Implementar las seis operaciones de `RepositorioAuth` con Supabase Auth:
   registro, inicio, recuperación, cambio de contraseña, cierre y flujo de
   sesión actual.
3. Enviar al alta los metadatos exactos `nombre`, `apellidos`, `telefono` y
   `rol`; el teléfono nulo se omite.
4. Exigir que el registro produzca una sesión activa y mapear la sesión y el
   usuario de Auth a los modelos de dominio sin persistir tokens manualmente.
5. Traducir excepciones de Supabase/Ktor al catálogo `TipoError`, sin dejar
   que excepciones de infraestructura crucen hacia dominio o UI.
6. Enviar la recuperación con
   `mx.donchambitas.app://auth/recuperar-contrasena`, sin revelar si el correo
   existe.
7. Declarar el `intent-filter`, entregar el `Intent` a `supabase-kt` y hacer
   que Navigation Compose aterrice ese URI en P-18.
8. Cambiar en Hilt solo el enlace de `RepositorioAuth`; los otros nueve
   repositorios permanecen falsos.
9. Probar el mapeo, la traducción de errores y el enlace profundo sin depender
   de la red en las pruebas automatizadas.

## Configuración externa requerida

Estas acciones se documentan y verifican, pero no se automatizan desde el
repositorio:

- Desactivar **Confirm email** en Supabase Auth para cumplir `DEC-25`.
- Agregar `mx.donchambitas.app://auth/recuperar-contrasena` a **Redirect URLs**.
- Definir `SUPABASE_URL` y `SUPABASE_ANON_KEY` en `local.properties` local.

Nunca se agrega `service_role` ni la llave de OpenAI al proyecto.

## Criterios de aceptación

- [ ] `RepositorioAuthSupabase` implementa las seis operaciones del contrato y
      ninguna excepción de infraestructura sale del repositorio.
- [ ] `registrar` manda los cuatro metadatos, omite el teléfono nulo, devuelve
      `Resultado<Sesion>` y falla si Supabase no deja sesión activa.
- [ ] `iniciarSesion` devuelve la sesión autenticada y las credenciales
      rechazadas se traducen a `TipoError.AUTENTICACION`.
- [ ] `recuperarContrasena` usa exactamente la URL acordada y conserva la
      respuesta opaca para correos inexistentes.
- [ ] `cambiarContrasena` exige sesión activa y `cerrarSesion` elimina la
      sesión administrada por `supabase-kt`.
- [ ] `sesionActual()` refleja `Authenticated`, `NotAuthenticated` y
      `RefreshFailure` como `Sesion` o `null`.
- [ ] El enlace `mx.donchambitas.app://auth/recuperar-contrasena` abre la app,
      se entrega a `supabase-kt` y navega a P-18.
- [ ] Hilt inyecta la implementación real solo para `RepositorioAuth`; los
      otros nueve enlaces siguen apuntando a repositorios falsos.
- [ ] URL y `anon key` salen de `BuildConfig`; no existe `service_role`, llave
      de OpenAI ni secreto nuevo en archivos versionados.
- [ ] Las pruebas unitarias no usan red y cubren éxitos, sesión ausente y cada
      categoría de error traducida.
- [ ] La prueba instrumentada valida el enrutamiento del enlace a P-18 en el
      AVD Pixel 10.
- [ ] `assembleDebug`, `testDebugUnitTest` y `connectedDebugAndroidTest`
      terminan sin errores.
- [ ] La aplicación se instala, abre y recibe el enlace mediante `adb` en el
      emulador Pixel 10.
- [ ] `ESTADO.md`, `INDICE.md` y `BITACORA.md` reflejan el cierre de S2-T07.

## Validación manual

1. Configurar `SUPABASE_URL` y `SUPABASE_ANON_KEY` en `local.properties` sin
   versionarlos.
2. Instalar el APK debug en el AVD `Pixel_10`.
3. Abrir la aplicación y verificar que no se cierra al iniciar.
4. Ejecutar:
   `adb shell am start -W -a android.intent.action.VIEW -d "mx.donchambitas.app://auth/recuperar-contrasena" mx.donchambitas.app`.
5. Confirmar que la aplicación abre P-18.
6. Para verificar el correo real, desactivar Confirm email y registrar la URL
   de recuperación en la consola de Supabase; ninguna credencial se commitea.
