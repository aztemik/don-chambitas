## Objetivo

Construir los componentes de carga, vacío y error, y dejar establecido el patrón
que toda pantalla con datos va a usar.

## Contexto

`PROCESO.md` exige que toda pantalla con datos maneje los cuatro estados. Esta
tarea entrega las piezas para que cumplirlo sea trivial.

## Qué hacer

`Cargando` con indicador centrado en mostaza.

`EstadoVacio` con icono, título, mensaje y botón opcional. Se usa cuando no hay
resultados o no hay nada publicado todavía.

`EstadoError` con mensaje y botón de reintentar. El mensaje viene del
`TipoError` y **dice qué hacer**, no solo qué falló: para `RED`, "Revisa tu
conexión e intenta de nuevo"; para `LIMITE_IA`, "Alcanzaste el límite de hoy".

`ContenedorEstado` es el patrón: recibe `cargando`, `error`, `vacio` y el
contenido, y decide qué pintar. Con eso una pantalla resuelve los cuatro estados
en una sola envoltura.

```kotlin
ContenedorEstado(
    cargando = estado.cargando,
    error = estado.error,
    vacio = estado.lista.isEmpty(),
    alReintentar = viewModel::recargar
) { /* contenido */ }
```

## Criterios de aceptación

- [ ] Los cuatro componentes existen con su `@Preview`
- [ ] `EstadoError` tiene un mensaje distinto por cada valor de `TipoError`
- [ ] Todos los mensajes de error dicen qué hacer, no solo qué falló
- [ ] `ContenedorEstado` cubre los cuatro casos y ninguno se pinta encima de otro
- [ ] Los textos viven en `strings.xml`, no dentro de los composables

## Cómo probarlo

En la vista previa, renderiza `ContenedorEstado` con las cuatro combinaciones y
confirma que solo se pinta una a la vez.
